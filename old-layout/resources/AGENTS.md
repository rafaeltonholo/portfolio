# resources - i18n + Markdown Models

This module owns two code-generation pipelines that `:site` depends on:

1. **Lyricist i18n**: string registries organized by feature, generated by the
   `cafe.adriel.lyricist:lyricist-processor` KSP processor.
2. **Marktdown models**: data models for every Markdown file in
   `resources/markdown/`, generated by the `dev.tonholo.marktdown` Gradle
   plugin. Renderer generation is intentionally disabled here and performed
   in `:site` instead.

Read [../.ai/guidelines.md](../.ai/guidelines.md) first.

## Source Structure

```
resources/
├── markdown/                          # Source Markdown articles
│   ├── hello-world-en.md
│   └── hello-world-pt-br.md
└── src/commonMain/kotlin/dev/tonholo/portfolio/
    ├── locale/                        # Locale enum + helpers
    └── resources/
        ├── pages/                     # Per-page string groups
        ├── projects/                  # Project descriptions + metadata
        └── workExperience/            # Resume data (companies, roles, dates)
```

## Marktdown Pipeline

`resources/build.gradle.kts`:

```kotlin
marktdown {
    packageName = "dev.tonholo.portfolio"
    models {
        srcDir(layout.projectDirectory.dir("markdown"))
    }
    renderers {
        disableGeneration()
    }
}

dependencies {
    add("kspJs", libs.lyricist.processor)
}
```

The paired configuration lives in `site/build.gradle.kts`, which sets
`renderers.modelsContainerProject = projects.resources.dependencyProject` and
points `models.srcDir` at this module's generated output. Any change to either
half requires updating the other.

## Conventions

- **One authoritative string per locale.** String registries live here; `:site`
  consumes them through its `locale/` wrapper. Do not duplicate UI copy into
  `:site`.
- **Group by feature.** New strings go under `resources/<feature>/` matching
  the feature name in `:site`.
- **Add new article = new Markdown file.** Drop the file into
  `resources/markdown/` using the existing `<slug>-<locale>.md` convention,
  then rerun `./gradlew :resources:kspCommonMainKotlinMetadata` followed by
  `./gradlew :site:kspKotlinJs`. Register the resulting route in
  `site/build.gradle.kts` via `addExtraRoute(...)`.
- **Public types only.** Lyricist and Marktdown KSP processors only discover
  public declarations.

## Common Commands

```bash
./gradlew :resources:build
./gradlew :resources:kspCommonMainKotlinMetadata   # Lyricist + Marktdown models
./gradlew :resources:kspJs                          # If JS-specific processing is added
```
